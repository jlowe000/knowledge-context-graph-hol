## Reproduce the component checks

`tests/test_scenarios.py` executes the same core topic-join SPARQL shape against the real generated RDF using RDFLib. It asserts that removing Graph capabilities removes S06 eligibility while preserving S02, and that changing only the objective does not claim a changed retrieval set.

The Oracle scripts under `integration-test/verify_*components.sql` and `verify_apex_callback.sql` are **isolated component tests**, not installation scripts. They use `integration-test/mocks/native_services.sql` in KCV_HOL_TEST only. `build_local_fixture.py` produces ignored SQL from the public dataset after local prepare. Their schema guard prevents accidental use of the service mocks in KCV_LAB. No existing application/schema is dropped or reset. Local test provisioning uses the already available environment; it is not a runtime dependency of the standalone lab.

The APEX test requires an isolated imported application with the test ID named in the script. It initializes a real APEX session and invokes the actual adapter while the RDF and model packages resolve to local mocks. It tests authentication/session ownership and transport but does not test an HTTP login, native graph reasoning or actual OCI inference.

## Deliberate limits

Retrieval follows explicit topic membership, deterministic ordering and bounded pages, not vector similarity or a learned ranking. Context weights are stored but do not change ordering in the extension. Source-concept extraction uses a constrained vocabulary in separate proposed graphs; these are not automatically mixed into active recommendations. Failed RDF DDL may leave an unreferenced lab graph to inspect; the mutation lease prevents a partially built revision from becoming the active scenario. A process terminated during APPLYING can leave a lease that an administrator must inspect before clearing; there is no background repair job.

The app is for public sample content and fictional contexts. It has not been assessed as a production identity, entitlement or availability-governance system.
