# Create and Revisit Your Own Context

## Introduction

Use the public knowledge collection with your own learning question. Save the situation, inspect evidence, refine your focus and return to the same work later. This is an app-user lab; no SQL or cloud-console access is needed.

Estimated Lab Time: 30–45 minutes plus model response and source-reading time; planning estimate.

### Objectives

- Create an owned draft, including an objective that is still emerging.
- Distinguish a saved draft, a ready revision and a conversation's selected revision.
- Inspect evidence and retain observations without changing public source knowledge.
- Search, reopen and archive your own work.

### Prerequisites

A working v2 application and **your own app account**. My Contexts belongs to the signed-in account in this application. Sharing a login shares its library. Use synthetic information while learning. Chat questions send context to the configured chat service; local library search uses a separate in-database model.

## Task 1: Save a starting point

1. Open **My Contexts**, select **Create context** and enter **Project information learning path**. Select **Save draft**. A name alone is sufficient.
2. Open **Edit Draft**. Enter **Which approaches could help me find relevant project information?** as the starting question. Leave objective clarity emerging if you are still deciding what matters. Supply a learning purpose, background, unknowns and actual constraints where useful.
3. Select eligible topics such as **Semantic retrieval** and **Ontology**, then save. Topics come from the installed collection. Removing a topic changes learning focus; it does not prohibit that technology.

**Expected outcome:** your draft is saved. No ready graph revision or model answer has been created. Saving can update private search embeddings inside the database.

Alternatively, use **Sample Contexts** → choose Alex, Sam or Casey → enter your context name → **Save as my draft**. This copies starting suggestions while clearing fictional identity/background and other personal framing. **Explore the samples** opens the separate fictional demonstration instead.

## Task 2: Review before using the context

1. From the overview, select **Review and Apply**. Read the before/after comparison. Cancel once to confirm review alone changes nothing.
2. Review again. A starting question and at least one eligible topic are required; a **Defined** objective also needs objective text. If changing collection/topics, use **Refresh preview for selected collection and topics** before applying.
3. Select **Apply reviewed context** only after checking the comparison.

**Expected outcome:** a private immutable revision is ready. Shared public knowledge is unchanged. An Active context can later have an incomplete edited draft while its existing ready revision remains usable.

## Task 3: Ask and inspect the answer

1. Select **Start a new conversation**. Ask: **What should I explore first, and what evidence supports that suggestion?** Wait for completion; do not submit repeatedly.
2. Open **How was this answer built?** Inspect the saved context, Sources graph, Answer lineage, returned passages and citation matches.
3. Follow a public source link and compare the editorial summary with the original. Distinguish source statements from proposed relevance to your situation.

**Expected outcome:** the explanation shows application-retrieved evidence captured before the model request. It records observable inputs and citations, not private model reasoning or proof of business value. Viewing it makes no chat request. An incomplete or failed response is not an accepted answer.

## Task 4: Refine deliberately

1. Save an observation describing a source check, discussion, vote, practical test or another way you checked understanding. Add a next question if helpful.
2. Return to the full editor. Change an objective or remove a topic, save, review and apply.
3. Reopen the existing conversation. It still uses its earlier revision. Select **Use the latest ready revision** when you want future questions to use the new context.
4. Ask a follow-up. Reopen the earlier answer's explanation and compare its original topics/evidence with the new response.

**Expected outcome:** observations belong to the revision where they were made. Applying advances the context head; adoption changes this conversation's future questions. Earlier answers stay historical. Neither an observation nor a chat suggestion automatically edits context or source knowledge.

## Task 5: Find and reopen saved work

1. Return to **My Contexts**. Search for its title, objective wording or a description of what you want to learn. Read **Saved objective**, **Why it matched** and the coverage notice. A preview is at most 240 characters, ending in `...` when truncated.
2. Try **All**, **Draft**, **Active** and **Archived** filters. Clear search and select All for recent contexts. See [search behavior](../../docs/context-search.md) for semantic/keyword limits.
3. Sign out and back in with the same account. Open the context and its saved conversation.

**Expected outcome:** saved work persists across sign-ins. Search uses saved context details, not chat transcripts. Edits can change result ordering; it is not a frozen snapshot.

## Task 6: Manage the library

Archive a disposable context. Find it with **Status → Archived**, open it and select **Unarchive**. Its previous Draft/Active state and history return. **Duplicate** creates another draft without copying conversations or observations.

**Delete Context** is a separate permanent action: review the title/counts, then cancel if unsure. Only confirm for disposable data you intend to remove. **Deletion unfinished** offers an explicit retry. Deletion cannot be reversed by Unarchive and does not promise erasure of platform audit records or backups. Public knowledge and independent copies remain separate. Check [validation status](../../docs/scenario-validation.md) for tested scope.
