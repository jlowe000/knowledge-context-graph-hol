## Design and test findings

The implementation uses a shared schema/migration contract, separate owner and authenticated APEX execution guards, explicit maintenance, fixed credential creation and recorded application evidence. Those are the intended boundaries; local string/behavior tests do not replace native or browser proof of them.

- [Credential contract tests](../tests/test_deployment_credential.py) check bounded validation, authorization order, secret-free journal inputs, replay/duplicate placement and pre-creation invalidation. They do not compile PL/SQL or exercise native credential mutation and concurrency. Keep successful source tests distinct from the outstanding runtime cases above.
- [Credential UI tests](../tests/test_apex_credential_ui.py) exercise source controls and browser-event clearing. Actual r12 request/debug/session/export evidence supplies the measured platform coverage; empty audit output remains a coverage gap.
- [The native setup authorization harness](../integration-test/verify_apex_deployment.sql) checks installer identity, two learners, anonymous callers and older setup actions with no model/network requests. It explicitly excludes browser sign-in, cross-workspace and recovery/concurrency proof. Its operation list predates `CREATE_OCI_CREDENTIAL`; the later private native credential checks are separate evidence, not coverage supplied by that file.
- The [admission holder](../integration-test/verify_deployment_admission_holder.sql) and [contender](../integration-test/verify_deployment_admission_contender.sql) are prepared native tests whose guards name earlier isolated owners. Review and retarget them narrowly before using the current build; do not remove owner checks or run them unchanged against a different installation. Their receipt cleanup is limited to their own token, and a missed timing window must fail rather than pass silently.
- [Cleanup tests](../tests/test_deployment_cleanup.py) and the earlier native fault/lock check support their particular failure paths. They do not prove that every interrupted browser request, DDL step or loader activation is recoverable.
- A bare context-overview route after session loss still lacks its required context ID. **My Contexts → select the context** is the verified workaround. A future redirect should apply only when the ID is absent; an invalid or another user's supplied ID must still encounter the ownership guard. No such fix is claimed here.

Historical pending fields retain their original checkpoint scope. Both current prepared-environment core paths now passed through final learner persistence, with the exact attachment allowances stated above. Use the latest review checkpoint without relabelling earlier failures or unfinished runs.

The first current replay harness needed its application-table inventory corrected to exclude native RDF support tables. Its failure remains a harness diagnostic; the corrected fixture produced the recorded replay and isolation results without a product change.

Browser inspection timed out during the single populated-upgrade submission. An early native observer compiled before the new contract package existed and saw the old 96-receipt prefix. A fresh browser later showed the successful upgrade summary and current native verification passed. This is a premature-observer diagnostic, not a failed product upgrade or a reason to resubmit.
